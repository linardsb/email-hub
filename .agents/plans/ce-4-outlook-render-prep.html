Getting ready for real Outlook screenshots

Brief for ce-4-outlook-render-prep.md (issue #422, part 1). The plan is the source of truth.

What we're building and why

Today nobody can see how our emails look in desktop Outlook; we only guess from the code. After this, the options for getting real screenshots are written down, and each design is packaged so any option can render it.

The concepts this plan rests on

Desktop Outlook draws email with Word

Classic Outlook on Windows uses Microsoft Word's layout engine (the code that turns HTML into pixels), not a browser. So a Chrome screenshot says nothing about it. Every option in the plan must run the real Word engine.

VML: Outlook-only drawing code

Word ignores rounded corners in CSS. Emails therefore include VML (an old Microsoft drawing language) inside comments only Outlook reads. Our buttons use it, and only a real Outlook render shows whether they come out right.

<!--[if mso]>
  <v:roundrect arcsize="20%" fillcolor="#4e3092">…
<![endif]-->

Images must be reachable from outside

Our converter points images at our own server (/api/v1/…), which a rendering service can't reach. The export copies each image next to the HTML, or rewrites links to a public address. Like posting a letter with a full address instead of "the house next door".

Placeholders that look real

The existing Litmus and Email on Acid code is a placeholder: it returns made-up screenshot links. Building on it would produce fake evidence, so this plan logs it as a known bug instead.

How the pieces fit

Figma design files→ converter HTML→ export bundle: HTML + images→ chosen render source (later)→ Outlook screenshots + button report (later)

Solid boxes ship now. Dashed boxes wait for your choice of Litmus, Email on Acid, or our own Windows machine.
